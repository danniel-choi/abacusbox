# 월 500만 원 수익화 운영 스코어카드

작성일: 2026-11-26  
목표: 광고·디지털 상품·B2B 수익을 합산한 월 매출 5,000,000원

이 문서는 목표를 보장하는 예측표가 아니라, 실제 데이터가 들어올 때 다음 작업을 선택하기 위한 운영 기준이다. 방문자 수, 광고 RPM, 전환율, 상품 가격은 실제 보고서에 기록되기 전까지 비워 둔다.

## 1. 월 매출 산식

`월 합계 = AdSense 실제 수익 + 디지털 상품 순매출 + B2B 계약·유지보수 순매출 + 제휴·후원 수익`

광고만으로 목표를 검토할 때는 다음 산식을 사용한다.

`필요 페이지뷰 = 목표 광고 수익 ÷ 실제 페이지 RPM × 1,000`

상품과 B2B는 결제 수수료, 환불, 세금, 외주·지원 비용을 뺀 순매출로 기록한다. 실제 단가가 없는 상태에서 필요한 판매량이나 계약 건수를 확정하지 않는다. `/calculators/revenue-goal-planner`의 기본값은 사례 입력값이다.

## 2. 매주 확인할 표

| 영역 | 확인할 실제 지표 | 다음 행동을 결정하는 기준 |
| --- | --- | --- |
| 검색 | 노출, 클릭, CTR, 평균 순위, 페이지별 유입 | 노출이 생긴 URL부터 제목·설명·내부 링크를 개선 |
| 계산기 | `calculator_view`, `calculator_start`, `calculator_result_view`, `calculator_complete` | 시작은 있으나 결과 확인이 낮으면 결과 이동 버튼과 입력 흐름 개선 |
| 광고 | 광고 노출수, 페이지 RPM, 슬롯별 가시성, CLS | 정책을 지키면서 가시성과 레이아웃 이동을 점검 |
| 무료 상품 | `template_download`, `template_preview_start` | 다운로드가 생기면 맞춤 항목 수요와 후속 문의를 비교 |
| B2B | `business_lead_submit`, 문의 유형, 데모 클릭 | 문의가 생긴 유형부터 요구사항·범위·견적을 검증 |
| 매출 | 결제액, 환불액, 수수료, 순매출 | 순매출 기준으로 다음 달 목표 배분을 재계산 |

데이터가 없는 지표는 0으로 간주하지 않고 `미확인`으로 기록한다. 이벤트가 없다는 사실만으로 사용자가 없거나 상품 수요가 없다고 결론내리지 않는다.

## 3. 30일 실행 순서

### 1주차: 측정 정상 여부

- GA4에서 공개 페이지의 이벤트가 수집되는지 확인한다.
- 관리자 페이지가 공개 성과 데이터에 섞이지 않는지 확인한다.
- Search Console 사이트맵 상태와 핵심 URL 검사 결과를 기록한다.
- AdSense 보고서에서 계정·페이지 RPM을 확인한다. 계정 목록이 비어 있으면 수익을 추정하지 않는다.

### 2주차: 검색 유입과 계산 완료

- 실제 노출이 발생한 계산기 3~5개를 선정한다.
- 각 페이지의 공식, 기준일, 입력 조건, 예시, 한계, 관련 계산기를 점검한다.
- 조회 대비 계산 시작·완료 흐름을 비교한다.
- 색인되지 않은 URL은 사이트맵·내부 링크·canonical·robots 설정을 먼저 확인한 뒤 Search Console에서 재검사한다.

### 3주차: 무료 상품 수요 검증

- 사업자 마진 템플릿 다운로드 수와 미리보기 시작 수를 비교한다.
- 다운로드 후 맞춤 템플릿 문의까지 이어지는지 확인한다.
- 문의가 반복되는 항목만 유료 상품 후보로 만든다.
- 결제·환불·세금·개인정보 처리 주체가 정해지기 전에는 자동 결제를 열지 않는다.

### 4주차: B2B 제안 검증

- 위젯 데모 클릭과 실제 문의를 분리해 기록한다.
- 문의별로 필요한 계산 공식, 입력값, 임베드 방식, 유지보수 범위를 정리한다.
- 동일 요구가 반복될 때만 표준 패키지와 가격 실험을 설계한다.
- 첫 계약 전에는 API 키, 사용량 제한, 장애 안내, 입력값 보관 정책을 확정한다.

## 4. 목표 배분을 바꾸는 규칙

- 광고 수익과 실제 RPM이 확인되기 전에는 광고 목표 비중을 확정하지 않는다.
- 상품 다운로드는 판매가 아니므로 상품 매출로 집계하지 않는다.
- 문의는 계약이 아니므로 B2B 매출로 집계하지 않는다.
- 7일 이상 실제 데이터가 쌓인 뒤에만 유입·사용·전환 중 가장 큰 병목을 다음 개발 우선순위로 정한다.
- 목표 달성 여부는 총매출이 아니라 환불·수수료·세금을 반영한 순매출로 다시 확인한다.

## 5. 현재 확인된 출발점

2026-11-28 Google 읽기 전용 스냅샷 기준 최근 28일 Search Console은 클릭 4회, 노출 29회였다. GA4는 세션 101, 활성 사용자 88, 페이지 조회 738으로 확인됐다. 이벤트는 `ad_slot_view` 240, `calculator_start` 103, `calculator_view` 50, `calculator_complete` 24, `calculator_result_view` 1이었다. 페이지별로 리니지 클래식 축캐 계산기 세션 47·시작 45·완료 21, MBTI 궁합 계산기 시작 7이 확인됐다. `share_click`은 이번 변경부터 페이지별로 수집한다. 무료 템플릿·B2B 전환 이벤트는 아직 관측되지 않았고, AdSense 계정 목록 0개와 지정 계정 조회 HTTP 404로 RPM·수익을 산정하지 않았다.

읽기 전용 Google 데이터 수집과 KPI 리포트 생성은 GitHub Actions에서 성공했으며, 스냅샷과 리포트 아티팩트를 30일 보관한다. Search Console 사이트맵 제출 쓰기 요청은 HTTP 403으로 남아 있으므로 제출 성공이나 색인 요청 성공으로 기록하지 않는다.

따라서 현재 단계의 목표는 500만 원을 달성했다고 주장하는 것이 아니라, 실제 매출로 이어지는 유입·계산 완료·다운로드·문의·계약의 연결을 측정 가능한 상태로 만드는 것이다.
