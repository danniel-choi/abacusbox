# AbacusBox 월 500만 원 수익화 실행 계획

작성일: 2026-11-25  
목표: 광고·디지털 상품·B2B 수익을 합산한 월 매출 5,000,000원

## 1. 목표의 전제

월 500만 원은 보장 수익이 아니라 운영 목표다. 현재 저장소에서 Search Console, GA4 Data API, AdSense 보고서의 실제 실적값을 확인할 수 있는 상태는 아니므로 방문자 수, 검색 순위, RPM, 전환율을 사실처럼 사용하지 않는다.

AdSense만으로 목표를 달성할 수 있는지는 실제 페이지뷰와 페이지 RPM을 확인한 뒤 판단한다. 기본 산식은 다음과 같다.

`월 광고 수익 = 월 페이지뷰 ÷ 1,000 × 페이지 RPM`

따라서 수익원 하나에 의존하지 않고, 검색 유입을 늘리는 동시에 반복 판매 가능한 디지털 상품과 사업자용 도구를 준비한다.

## 2. 권장 수익 구조(운영 목표)

아래 금액은 현재 실적이 아니라 목표 배분 예시다.

| 수익원 | 월 목표 범위 | 핵심 조건 |
| --- | ---: | --- |
| AdSense | 1,500,000~2,000,000원 | 유효 페이지뷰, 정책 준수 광고 배치, 계산기별 RPM 측정 |
| 디지털 상품 | 1,000,000~1,500,000원 | 세무·급여·대출·사업자용 템플릿과 결과 리포트 |
| B2B 위젯/API | 1,000,000~2,000,000원 | 외부 사이트 임베드, 브랜드 제거·사용량·지원 요금제 |
| 제휴·후원 | 500,000~1,000,000원 | 광고·제휴 표시, 독립적인 편집 기준, 정책 검토 |
| 합계 | 4,000,000~6,500,000원 | 실제 데이터로 분기별 재배분 |

## 3. 단계별 실행 순서

### 1단계 — 측정 기반 만들기

완료 기준:

- 계산기 페이지 조회, 입력 시작, 결과 보기, 결과 저장, 공유 이벤트를 GA4에서 구분
- 광고 슬롯 가시 노출 이벤트를 계산기·본문·상단·하단별로 구분
- Search Console과 AdSense의 실제 데이터가 없다는 사실을 운영 문서에 명시
- 월별 KPI 표를 만들고 추정값과 실제값을 분리

이번 단계에서 계산기 페이지는 `calculator_view`, `calculator_start`, `calculator_result_view`, `calculator_complete` 이벤트를 사용한다. 결과 영역을 실제로 본 시점을 별도로 기록해 입력 시작 대비 결과 확인 흐름을 구분한다. 개인정보·입력 원문·검색어는 이벤트에 보내지 않는다.

### 2단계 — 고의도 계산기 20개 집중 개선

우선순위는 급여·세금·대출·부동산·사업자 계산기다. 각 페이지에 공식, 기준일, 입력 조건, 예시, 한계, 공식 출처, 관련 계산기를 연결한다. 실제 검색 실적이 확인되면 클릭·노출·CTR 순으로 우선순위를 다시 정한다.

현재는 외부 검색 실적이 없어 다음 5개를 임시 핵심군으로 선정했다: 최저임금, 퇴직금, 연봉 실수령액, 대출 DSR/LTV, 대출 이자. 이 페이지들에는 대표 입력값을 불러오는 빠른 예시와 관련 계산기 이동 측정을 적용해 사용자의 계산 시작·완료 흐름을 비교할 수 있게 한다. 실제 성과가 확인되면 이 목록을 교체할 수 있다.

### 3단계 — 검색 유입용 주제 클러스터

계산기 하나를 얇은 글 여러 개로 복제하지 않고, 사용 상황별 가이드와 계산기 결과 해석을 묶는다. 대표 주제는 `연봉/실수령`, `대출/상환`, `부동산/세금`, `프리랜서·사업자`로 구성한다. 자동 생성 콘텐츠는 사람의 검수와 출처 확인을 거친 경우에만 공개한다.

### 4단계 — 광고 경험과 정책 점검

광고를 계산 버튼·메뉴·결과처럼 보이게 하지 않고, 입력창과 결과를 가리지 않도록 한다. 광고 슬롯별 가시성·레이아웃 이동·모바일 사용성을 실제 기기에서 점검한다. 광고 클릭 유도나 사적 문의 영역의 광고 배치는 금지한다.

### 5단계 — 유료 상품 검증

먼저 무료 샘플을 제공하고 다음 상품을 작은 범위로 검증한다.

- 급여·퇴직·세금 계산 결과를 정리한 엑셀/문서 템플릿
- 사업자용 견적·마진·부가세 관리 템플릿
- 계산 결과를 저장하고 공유하는 광고 없는 리포트

결제·환불·세금·개인정보 처리 기준과 운영 주체가 준비되기 전에는 결제 기능을 임의로 추가하지 않는다.

현재는 `/business`에 계산기 위젯·맞춤 도구, 사업자용 템플릿, 콘텐츠·제휴 검토의 세 가지 문의 동선을 공개하고 `business_lead_click` 이벤트로 수요를 측정한다. 문의 수와 실제 제공 가능 범위를 확인한 뒤 가격·결제 기능을 별도 결정한다. 문의 유형은 D1에 별도 저장하고 관리자 화면에서는 개인정보 없이 유형별 건수와 최근 접수 시각만 집계한다.

무료 검증 단계로 `/resources/business-template`에 사업자 마진 관리 CSV 샘플을 추가하고 `template_sample_click`, `template_download`, `template_lead_click` 이벤트를 기록한다. 결제·환불·세금 처리 주체가 정해지기 전에는 유료 결제를 구현하지 않는다.

### 6단계 — B2B 위젯/API

사용량 제한, API 키, 호출 로그, 장애 안내, 이용약관, 개인정보·입력값 보관 정책을 먼저 정의한다. 초기에는 민감한 입력값을 저장하지 않는 임베드형 계산기와 월 구독형 관리 화면을 우선 검토한다.

## 4. 매월 확인할 KPI

- 유입: Search Console 클릭·노출·CTR·평균순위, GA4 랜딩 페이지
- 사용: 계산기 조회 대비 입력 시작률, 결과 보기율, 저장·공유율
- 광고: 페이지 RPM, 광고 노출수, 슬롯별 가시성, CLS
- 상품: 상품 페이지 방문, 구매 전환율, 환불률, 순매출
- B2B: 리드 수, 데모 신청, 활성 고객, 고객당 월 매출, 이탈률

데이터가 없는 KPI는 `미확인`으로 기록한다. 목표를 달성하지 못한 원인을 추측하지 말고, 유입·사용·전환·단가 중 어느 단계가 막혔는지부터 분리한다.

읽기 전용 GA4 스냅샷은 페이지별 세션·활성 사용자·페이지뷰와 함께 이벤트별 발생량도 수집한다. 이벤트가 아직 충분히 쌓이지 않았으면 해당 KPI는 미확인으로 유지한다.

## 5. 외부 계정에서 필요한 작업

다음은 저장소만으로 완료할 수 없다.

- Search Console 속성의 검색 실적 및 URL 검사 확인
- GA4 Data API 조회 권한과 Property ID 확인
- AdSense 보고서 API 또는 계정 보고서의 페이지 RPM·예상 수입 확인
- 유료 상품을 운영할 경우 결제대행·환불·세금·약관 결정

인증 정보는 소스 코드와 문서에 기록하지 않고, 배포 환경의 시크릿으로만 관리한다.

## 6. 다음 실행 순서

1. 배포 후 GA4에서 `calculator_view/start/result_view/complete` 수집 여부 확인
2. 7일간 실제 데이터를 쌓고 상위 진입·사용 계산기 선정
3. 선정된 3~5개 계산기의 콘텐츠·내부 링크·결과 공유 개선
4. 무료 템플릿 1개를 공개하고 유료 수요를 측정
5. B2B 임베드 문의 폼과 데모 페이지를 만든 뒤 리드 수를 측정

## 7. 2026-11-26 실행 결과

주간 운영 판단 기준은 `docs/revenue-5m-operating-scorecard.md`에 별도로 기록했다. 실제 데이터가 없는 항목을 0 또는 예상치로 해석하지 않고, 검색·사용·광고·상품·B2B 지표가 확인될 때마다 다음 개선 작업을 선택하는 방식이다.

월 목표를 실제 운영 활동량으로 분해할 수 있도록 `/calculators/revenue-goal-planner`를 추가했다.

- 광고: 입력한 실제 페이지 RPM을 기준으로 필요한 월 페이지뷰를 역산
- 디지털 상품: 상품 1건 순매출과 전환율을 기준으로 필요한 판매량·상품 페이지 방문자를 역산
- B2B: 계약 1건 순매출을 기준으로 필요한 계약 수를 올림 계산
- 비중 합계가 100%가 아니어도 상대 비율을 자동 정규화
- SEO title, description, canonical, FAQ와 관련 계산기 내부 링크 추가
- `npm run ai:seo-check` 결과: 208개 계산기 HTML, 1,040 PASS / 0 FAIL

기본 입력값은 사례용이며 사이트의 실제 RPM, 전환율, 계약 단가나 매출을 의미하지 않는다. 실제 데이터가 확보되면 이 플래너의 입력값을 월별 측정값으로 교체하고, 결과와 실제 매출의 차이를 별도 기록한다.

2026-11-27 자동 측정 실행 결과, 최근 28일 Search Console은 클릭 4회·노출 29회, GA4는 세션 74·활성 사용자 62·페이지 조회 516으로 확인됐다. GA4 이벤트는 `ad_slot_view` 232회, `calculator_start` 79회, `calculator_view` 17회, `calculator_complete` 6회였다. 페이지별로 리니지 클래식 축캐 계산기는 시작 27회·완료 6회, MBTI 궁합 계산기는 시작 7회가 확인됐다. 새 `calculator_result_view` 이벤트는 배포 시점 이후부터 관찰하므로 이번 스냅샷에는 아직 포함되지 않았다. 이 수치는 수익이나 전환율을 의미하지 않으며, 표본이 작으므로 우선순위 판단용 출발점으로만 사용한다.

Google 서비스 계정 기반 읽기 전용 스냅샷과 KPI 리포트는 GitHub Actions에서 자동 생성·보관되도록 연결했다. AdSense API 응답의 계정 수가 0으로 확인되어 광고 RPM·수익은 산정하지 않았다. Search Console 사이트맵 제출 쓰기 요청은 HTTP 403이므로 사이트맵 제출 상태 변경이나 색인 요청 성공으로 해석하지 않는다. 신규 무료 템플릿·B2B 전환 이벤트도 아직 관측되지 않았다.
